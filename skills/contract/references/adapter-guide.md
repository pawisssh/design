# Adapter guide

What any Adapter must produce, whatever its Code Library. Read before writing a new Adapter skill, or a Contract by hand. The field-by-field rules are in the [Contract schema](contract-schema.md) and the [foundations schema](foundations-schema.md); this guide says how to get from source code to those documents. The Carbon Adapter ([`skills/adapter-carbon`](../../adapter-carbon/SKILL.md)) is the worked example, and its Button Contract is the reference output.

## What an Adapter is

One skill per Code Library, `skills/adapter-<key>/`, where `<key>` is the Contract's `source.adapter`. Adding a Code Library adds a sibling skill and changes nothing in `contract`, `to-preview` or `to-design`. An Adapter never touches Figma. It produces:

| Output | Where | Notes |
|---|---|---|
| A draft Contract per Component Family | `design-systems/<ds>/contracts/<family>.component.json` | Written from source by an agent following the Adapter's SKILL.md. `selection` starts as `{status: "draft", omit: [], expectedCount, approval: null}`. |
| The foundations document | `design-systems/<ds>/<ds>.foundations.json` | Generated by a script from the pinned token sources: the Code Library's whole theme, plus the component tokens of each Component Family that has a Contract (ADR 0006). An Adapter may take a flag for a family whose Contract does not exist yet (CDS's `--family`). The union of every Contract's tokens (`closure()`) is recorded, not the scope. Never edited by hand. |
| A source fetch | `skills/adapter-<key>/scripts/sources.mjs`, into gitignored `.scratch/adapter-<key>/` | Fetches the pinned files and checks each sha256. Runs no package install script. |
| A preview renderer | `skills/adapter-<key>/scripts/preview.mjs` | `previewRenderer(contract)`, the interface in [to-preview's page reference](../../to-preview/references/interactive-template.md). It renders the real Code Library component; it never approximates one. |

The source fetch reuses what the other Adapters export: `download`, `sha256` and `snapshotId` from [adapter-carbon's `sources.mjs`](../../adapter-carbon/scripts/sources.mjs), and `downloadVerified` and `installAtomically` (an npm tarball checked by its integrity, installed race-safe) from [adapter-generic's](../../adapter-generic/scripts/sources.mjs). [`scripts/fetch.mjs`](../../../scripts/fetch.mjs) and CI find it by its name; keep its folder in the clean step of `.github/workflows/test.yml`, which `.github/test/fetch.test.mjs` checks.

Not an Adapter's job: Figma ids, build plans, approvals and the owner's omit list. Computed bounds from a browser render are validation evidence, never Contract values. Themes are foundations modes, never variants or a per-specimen field.

## 1. Pin the source

- Pin one repository commit (the dereferenced commit, not an annotated tag object) and the exact version of every package the Contract or the renderer uses (`source.packages`).
- Read values only from that pin. The Code Library's own Figma file is at most a structure reference (page layout, layer names); never take a value from it.
- Record every file you read in `source.files` as `sha256:<hex>` of its bytes, and compute `snapshotId`: `sha256:` of the `shasum -a 256` manifest (one `<hex>  <path>\n` line per file, sorted by path in byte order). In a shell, from the folder the paths are relative to: `printf '%s\n' <path>... | LC_ALL=C sort | xargs shasum -a 256 | shasum -a 256`. A moved pin is a new snapshot, and it voids any approval.

## 2. Find the variants

1. **Axes are the finite visual product**: the values that change geometry or paint (size, hierarchy or kind, state, finite structure changes). Free text, icon choice, callbacks, refs and telemetry ids are not axes.
2. **Cross-check every value against the styles.** A value the types accept but no style rule styles is not a variant: record it in the axis `dropped` list with `reason` and `evidence` (Carbon's `danger--primary`). Treat docs, types and styles as three witnesses; when they disagree, record which one won in `defaultSource`, `evidence` or a note.
3. **Keys and labels.** Each value's `key` is the code value (identity, never renamed), `label` is Title Case for Figma `Prop=Value`, `code` is the props that render it. A value that is two props in code is still one value (`lg-expressive` → `{size: "lg", isExpressive: true}`).
4. **Defaults.** Every axis has `default` and a `defaultSource` (where in the source the default comes from). The all-defaults tuple is the Base Component.
5. **State is canonical.** Map the CSS pseudo-classes and state classes onto `enabled, hover, active, focus, disabled`, keep only the states the styles define for the family, and record each one's selector in `css`. A state code cannot set through props has `code: null`; the preview forces it through `css`.
6. **Exclusions are the source's, not the owner's.** Put in `excluded` only combinations the source makes impossible, each with `reason` and `evidence`. What the owner does not want goes in `selection.omit` later, through To-preview.

## 3. Anatomy and properties

- **One anatomy per family.** Record each layout-owning container and its visual children, in order. Keep nested containers that own layout, clipping or paint; drop inert wrappers. A state or size never changes the tree; a real structure change is another axis value or another family.
- **Layer names are final Figma names**, unique in the tree. Rules address nodes by name.
- **Each source capability maps to one native representation:**

| Source capability | In the Contract | Evidence to check |
|---|---|---|
| Finite size, kind or state | an axis value | every selected tuple |
| Independent optional content | a `BOOLEAN` property bound to `visible` | each placement it affects, per `match` |
| Free text | a `TEXT` property bound to `characters` | default and long copy |
| Icon choice | an `INSTANCE_SWAP` property bound to `mainComponent`, plus `icons` | default and another real icon |
| Theme | foundations modes | every mode, never a variant |
| Styling set by an ancestor (Carbon Layer level) | foundations modes; bind the name the Code Library's CSS uses (`field` where Carbon writes `$field`, `field-01` where it writes `$field-01`), ADR 0012 | each Layer Mode, never a variant |
| Finite structure change | an axis value or a separate family | every structure |
| Selected, checked or open | a value of its own axis (State stays canonical), or a nested component when only a child changes | each value in every State |
| Callback, ref, telemetry id | nothing (code only) | — |

A BOOLEAN may bind different nodes on different variants (`binds[].match`), and every selected variant needs exactly one bind per property. Choose by actual behaviour: if a loading state moves the label or changes the width, it is a variant, not a BOOLEAN.

## 4. Layout and paint rules

**Cascade → ordered rules.** Walk the stylesheet from the general selector to the specific ones and write `layout` and `paint` as ordered `{match, set}` lists: the base rule matches `{}`, then one rule per modifier class, then state rules. A later rule wins per field, which is all the cascade logic the builder has. Write a field once in the rule that the CSS sets it in; do not pre-resolve variants, so each value stays explainable by one rule. A required field left unresolved for a selected variant makes the Contract invalid.

**CSS to layout fields.** Read the authored CSS and the DOM together, not computed bounds: a computed 120px width may be `hug`, a fixed 120 or `fill`. Positional inference is supporting evidence only.

| Code evidence | Contract field | Watch for |
|---|---|---|
| `display: flex`, `flex-direction: row / column`; a block stack | `direction: row / column` | Reverse directions need explicit child order. Grid layouts need nested rows and columns or a note. |
| `justify-content: flex-start / center / flex-end / space-between` | `alignMain: start / center / end / space-between` | Main axis follows `direction`; space-between is not a gap. |
| `align-items` | `alignCross` | `stretch` is the child's `fill` on the cross axis, not an alignment. |
| `flex-wrap: wrap` | nothing: the Contract has no wrap field | Model the rows as nested containers, or record a note. |
| `gap`, `row-gap`, `column-gap` | `gap` | A row's gap is `column-gap`; a column's is `row-gap`. |
| `padding` (logical or physical sides) | `paddingTop/Right/Bottom/Left` | Resolve logical sides with the writing direction. |
| Intrinsic, shrink-to-fit size | `width` / `height`: `hug` | Check min/max and text wrapping. |
| `flex: 1`, `flex-grow`, `width: 100%`, `align-self: stretch` | `fill` | Only when the parent supports it; avoid a `hug` parent with a `fill` child on the same axis. |
| A definite size | a token or raw value | Account for `box-sizing` and the border. |
| `min-/max-` sizes (`min-block-size`) | `minWidth`, `maxWidth`, `minHeight`, `maxHeight` | A min height with hugging content reproduces CSS `min-block-size`. |
| `border-radius` | `radius` | Percentages and pills need geometry. |
| `border` | `stroke`, `strokeWeight`, `strokeAlign: inside` | `inside` is not `box-sizing: border-box`; outlines are not interchangeable with strokes. |
| Font family, size, weight, line height, tracking | `textStyle` (a type token) | Use the real font. |
| `white-space` and wrapping | `textResize` | Single-line labels hug (`width-and-height`); wrapping needs a constrained width. |
| `background-color`, `color`, `border-color` | `fill` (the text colour on a TEXT node), `stroke` | Keep the token, not the hex. |
| `transparent` | `"none"` | Neither raw nor a warning. |
| `currentColor` | `{sameAs: "Node.field"}` | Resolved after every rule. |
| `box-shadow` | `effects`, **reversed** | CSS lists the top shadow first; Figma paints later entries on top. The stroke paints above inner shadows. |
| `opacity` | `opacity` | It also dims descendants. |
| `position: absolute` overlays, centred | `position: "absolute"`, `constraints: {horizontal: "center", vertical: "center"}`, a fixed `width` and `height` | Only centring for now: an offset overlay (a badge) is a note. The parent needs Auto Layout; put the node under the box it centres on (CDS's spinner sits in `Middle`, not the root). |
| A drawn circle or arc: an SVG `<circle>` stroke, `stroke-dasharray` / `stroke-dashoffset` | an `ELLIPSE` with `arc: {start, sweep}`, `strokeCap`, `strokeWeight`, `stroke` | 0° is 12 o'clock, clockwise; resolve `rotate` into `start`. The stroke lies inside the box, so an SVG r = 11 in a 24-box is `width: 24`, `strokeWeight: 2`. An arc's parent is a FRAME with `direction: "none"`; stacked shapes (track, then arc) are its children in order. An animated shape is a still frame plus a note. |

**Values.** Bind every token-backed value as `{token: "<flat name>"}`, the Code Library's own name. A value with no token is `{raw, level, reason}`: `info` when derived from tokens (write the derivation, such as `(size − 1lh)/2`), `warning` when it is a constant with no token. A matching hex value is never a token binding.

## 5. Icons, Code Connect and notes

- `icons`: the icon package and version, the file path pattern with a fallback, the `default` and the `preferred` list (`default` must be in it). The icon colour per variant is a `paint` rule on the glyph's single `Vector`.
- `figma`: page (plural family name), Component Set name, description, Header (type, title, namespace) and `grid {columns, rows}` by axis keys.
- `code`: framework, package, component, import and `alwaysEmit` (props the snippet must always set, with `alwaysEmitWhy`), plus `required` (props the component needs that no axis value or property sets, such as `id`) and `items` (a Repeated child's `{component, props}`) where the code has them (#93, see [contract-schema.md](contract-schema.md#code)). Per-value and per-property `code` sits next to the value or property, so Code Connect cannot drift from the axes.
- `notes`: every resolved disagreement and every check you could not run, with `level` and `at`. An open `warning` note blocks approval.

## 6. Foundations document

Generate it with a script, from the pinned token sources and the Contracts, following [Who writes it](foundations-schema.md#who-writes-it). Each Adapter names its Code Library's theme source and emits all of it, plus the component tokens of each family that has a Contract, each with `family`; the CDS Adapter also emits a family it is told about with `--family` before that Contract exists. A Code Library with no token file (CDS: its theme is TypeScript and its state colours are computed) may be read by evaluating its compiled modules, under the limits of [ADR 0021](../../../docs/adr/0021-an-adapter-may-evaluate-a-code-librarys-compiled-theme.md). Its state and scheme-pick colours become Synthesized tokens with an empty `codeSyntax` when no custom property holds them. The generator uses the shared module's `closure()` and `validate()`, never its own copy; fails and writes nothing on a validation rule 6 error, an unknown token, a source value it cannot read (naming the token), a Contract pinned to another commit, or a value that differs from the compiled CSS; and is byte-identical on a rerun (stable `documentHash`). Where the Code Library's own sources disagree with its compiled CSS, the document may take the CSS only for an explicit, listed set of values, each with a warning note and listed in `checks.css.differs`; a listed value that no longer differs fails too.

## 7. Hand over

1. `node skills/contract/scripts/check.mjs design-systems/<ds>/contracts/<family>.component.json` prints `OK` (it finds the foundations document next to `contracts/`; before the first foundations run, regenerate it first).
2. Regenerate the foundations document; it reports no error.
3. Render the default variant and a few others with the preview renderer and compare them with the Code Library's own render.
4. Hand the draft Contract to To-preview to narrow the selection (optional), then to To-design, whose base loop ends with the owner's approval.
